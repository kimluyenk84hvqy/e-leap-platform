# E-LEAP R1.5 — Identity, Access, Enrollment & Session Foundation (Preview)

## Locked rules
- Identity determines role; users do not choose production roles.
- Role determines capabilities; device never grants permission.
- QR/class code supplies session context only, never Teacher/Admin authority.
- Hosted Golden lessons inherit the platform role and may not self-escalate.
- Student/Guest hosted lessons hide Teacher/Presentation switches and Teacher tools.
- Teacher/Admin may teach and enter Presentation; content-edit grants remain separate.
- Student profile is intentionally minimal: Student ID, Full name, Student group (Undergraduate/Postgraduate), Gender (Male/Female), Research consent.
- Declining research consent does not restrict learning.
- Research exports use researchId, not Student ID/name.

## Preview limitation
This RC uses localStorage role claims so the interaction contract can be tested without changing Production.
It is **not** sufficient security for real learner data. Before Production launch with real accounts, replace preview claims with authenticated server-issued sessions/RBAC and protect direct standalone/resource URLs.

## Acceptance tests
1. Preview as Student -> open U1.1 -> only Student lesson mode; Teacher reveal unavailable.
2. Preview as Student -> open U1.2 -> only Student lesson mode; Teacher/Presentation unavailable.
3. Preview as Teacher -> U1.1/U1.2 open in Teacher; Presentation available.
4. Preview as Admin -> teaching tools available; content governance remains governed by R1/R2.
5. Guest -> only public/published scope; hosted lesson cannot escalate to Teacher.
6. Student profile form contains no age range and no self-rated English level.
